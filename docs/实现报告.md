## 3. 现状缺陷的处置对照

| 现状缺陷（需求专篇 §0） | 处置 |
|---|---|
| `n.find("云端")` 猜节点类型 | 类型**只由规则声明的 `typeKey`** 判定；未声明类型 → `1000` + 列出已声明 key；改名不影响类型（`model01` 用例 + 验收 C09/C09b/C10） |
| 前端做驼峰→下划线归一 | 归一上移到引擎：`ledgerKey`（规则声明）+ 通用 camel→snake 派生；`normalizedShape()` 给出单一形状；台账形状随 `ingest()` 返回（验收 C16/C17） |
| `bandwidth*1.12` / `latency*0.72` / `mesh+20` / `state='green'` | 全部移除；优化改为"可声明搜索空间 + 步长"驱动，只产出**建议值**（验收 C13 + `opt01`/`opt02`） |
| `bw = 46+46*(1-exp(-3.2t))` 这类写死曲线 | 曲线点由真实滑动窗口聚合产生（验收 C14 + `opt06`：恒定输入 → 曲线必须平） |
| 状态在阈值附近抖动 | 迟滞（双向不同阈值 + 连续 N 次确认）+ 最小驻留；`st02` 用例证明"变更次数 ≪ 越阈次数"（0 vs 19） |
| 无状态机 / 无留痕 | `StateChange` 记录从哪到哪、越阈阈值与当时得分、决定指标与数值、逐指标快照（`st04` 可复原判定） |

## 4. 设计口径（要点）

- **规则 vs 引擎**：节点类型、层级、结构、指标集、阈值、迟滞、评估算法与权重、搜索空间、曲线粒度
  全部住规则包；引擎只提供机制（派生输入是**文档化的闭集**，规则引用，超集即拒绝装载）。
- **状态输出**：只有 `green/yellow/red` 状态码；颜色到像素属 `map-2d` 主题（D4，验收 C15）。
- **首次落档 ≠ 变更**：拿到第一个可判定样本时直接落档（不写日志、不发事件）；事件语义严格等于"变化"。
- **无数据不判定**：没有窗口样本时不编造状态（`hasState=false`）；缺字段/无法解释的取值一律保持原值。
- **优化是纯函数**：建议 = f(当前窗口聚合, 规则)；连续 10 次逐字节一致；闭环（宿主把建议值灌回）收敛后返回"无改进"。
- **确定性**：节点按 id 升序、边按装载顺序、派生输入固定顺序、JSON 键序 = 声明顺序；不使用
  `unordered_map` 遍历序 / 指针 / 随机数 / 进程号 / 时区。
